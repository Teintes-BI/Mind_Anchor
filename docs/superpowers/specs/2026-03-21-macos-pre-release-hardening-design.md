# MindAnchor macOS 预发布收口设计

## Goal

定义 `MindAnchor` 下一阶段的唯一主目标：  
在不继续扩张 Android / 音视频 / 健康范围的前提下，把已经跑通的 `macOS` 主链路推进到**可预发布、可持续回归、可普通用户试用**的阶段。

这份设计承接：

- `docs/superpowers/specs/2026-03-19-mindanchor-v1-commercial-delivery-design.md`
- `docs/macos-mainline-runbook.md`

当前结论是：  
项目已经完成了“技术可行性证明”，下一阶段最值钱的工作不再是增加新输入源，而是把 Mac 主产品做得更稳、更完整、更接近真实交付。

## Current State

当前已经具备的能力：

- 原生 `SwiftUI + AppKit` Mac 客户端工作区已建立
- 登录、自举、状态栏、主窗口、提醒列表、ack 回写主链路已打通
- `macOS` 状态栏恢复主窗口自动验收已通过
- `desktop_local` 提醒主链路 E2E 已通过
- runbook 已明确当前开发级验收门槛

当前还不够“预发布”的部分：

- 首次启动与权限引导还不够完整
- 连接状态、失败原因、断网恢复、补传状态对普通用户还不够清楚
- 设置页、Today 页、Reminders 页还偏“开发可用”，离“产品可交付”仍有距离
- 打包、安装、开发签名级分发材料与预发布 checklist 还不完整

## Problem Statement

如果现在继续扩：

- Android
- iOS
- 音频 Beta
- 视频 Beta
- 健康桥接

会得到一个“输入源越来越多，但主产品还不够稳”的系统。

这会直接带来三个问题：

1. 主线焦点分散
2. 自动验收成本上升
3. 普通用户试用时感知不到“更完整”，只会感知到“不够成熟”

因此下一阶段应当明确切换目标：

**不再优先扩输入源，而是优先完成 Mac 主线的预发布收口。**

## Approaches

### 方案 A：Mac 预发布收口优先（推荐）

目标：

- 先把 `apps/macos` 做成一个稳定、完整、可反复验收的候选产品
- 以 `macOS` 为唯一主交付面
- Gateway / OpenClaw 只做支撑这条主线所需的稳定性补强

优点：

- 最符合当前仓库真实进展
- 对用户可感知价值最大
- 最容易形成清晰的预发布里程碑
- 风险边界最清楚

缺点：

- 会显式延后 Android / 音视频 / 健康的推进

### 方案 B：后端稳定性优先

目标：

- 优先强化 Gateway / OpenClaw
- 让 trace、fallback、提醒决策、可观测性更强
- Mac 客户端保持当前状态

优点：

- 服务端基础更硬
- 后续多端扩展更轻松

缺点：

- 普通用户几乎感知不到进步
- 不能尽快形成可试用的 Mac 候选版

### 方案 C：Web 控制台补完优先

目标：

- 强化 Dashboard、Reflections、Inbox、State
- 先把运营/复盘面做完整

优点：

- 展示层更完整
- 便于演示

缺点：

- 主采集端仍然不够成熟
- 不解决客户端预发布问题

## Chosen Direction

选择 **方案 A：Mac 预发布收口优先**。

原因：

- 它最贴合当前仓库已经跑通的事实基础
- 它能最快把项目推进到“可交付候选版”
- 它不会阻断后续 Android / 音视频 / 健康扩展，反而会为那些能力提供更稳的主产品底座

## Scope

下一阶段只聚焦四类内容。

### 1. 首次启动与权限闭环

补齐：

- 通知权限状态
- Accessibility / 前台窗口采集状态
- 缺失权限时的降级说明
- 首次启动自检与错误提示

目标不是新增复杂权限，而是让用户**知道当前缺什么、影响什么、怎么修复**。

### 2. 连接与稳定性闭环

补齐：

- 队列深度
- 最近同步时间
- 最近失败原因
- 心跳状态
- 断网缓存与恢复提示
- 提醒拉取/ack 失败时的用户可读错误

目标是把“能工作”升级为“用户知道它是否在工作”。

### 3. Mac 产品页收口

重点完善：

- `Today`
- `Reminders`
- `Settings`

其中：

- `Today` 聚焦当前状态、最近活动摘要、下一步建议
- `Reminders` 聚焦 pending / acknowledged、snooze、ack、来源说明
- `Settings` 聚焦账户、权限、连接、自检、日志导出

这一阶段不追求 UI 大改版，只追求完整、清楚、稳定。

### 4. 预发布交付材料

补齐：

- Mac 安装 / 启动 / 连接指引
- 预发布 checklist
- 开发签名级打包说明
- 故障排查与日志导出说明

这里的目标不是立刻上架，而是让“另一台 Mac 上的普通试用者”也能按文档完成试用。

## Non-Goals

以下内容明确不进入这一轮：

- Android / iOS 新功能开发
- 音频 Beta 深挖
- 视频 Beta 接入
- 健康桥接实现
- 正式 Apple 签名、公证、Sparkle 自动更新
- 多用户 / 团队能力
- Web 大规模重做

## Architecture Notes

这一轮不改总体架构。

继续保持：

- `apps/macos` 是唯一主客户端
- `apps/api` 作为 Gateway
- OpenClaw 是唯一智能中枢
- Web 继续作为辅助控制台

本轮只在这条架构下做**产品化收口**，不做新的大重构。

## Success Criteria

这一轮完成后，应该满足：

1. 新机器按文档可完成环境准备、运行与主链路验收
2. 普通用户可以理解当前账户、连接、权限、采集、提醒状态
3. 断网、权限缺失、Gateway 不可用等场景能给出明确反馈
4. `test:macos`、`test:macos:status-item`、`test:macos:reminder-e2e` 继续保持稳定
5. Mac 客户端达到“开发签名级预发布候选版”标准

## Delivery Shape

这一轮的交付物应包含：

- 一个新的实施计划
- 补强后的 `apps/macos`
- 必要的 `apps/api` 配套调整
- 更新后的运行/安装/排障文档
- 一套更清晰的预发布验收清单
